# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

QUEST: 2D tactical/roguelite game built in Godot 4.6, GDScript only (no C#/.NET), GL Compatibility renderer. A menu/character-select/save-slot shell, run under a `Main.tscn` scene orchestrator, around a *Dungeon of the Endless*-style gameplay scaffold (`Main2d.tscn`): pick a hero, spawn into a room/corridor graph (`RoomManager`) over a multi-room `TileMapLayer` floor with real HP (no combat stats), click a revealed room/corridor connected to the hero's current one to glide straight there, and a global turn that advances only when a door is opened — ticking a 4-resource economy (industry/food/science/dust) and revealing the next room+corridor (basic fog-of-war). Supports Steam multiplayer (Host/Join via GodotSteam lobbies with auth-ticket validation) alongside the offline single-player flow.

**Removed in `refactor/total-gameplay-wipe`:** the previous card-driven combat, procedural dungeon generation, and enemy AI systems were fully deleted (not archived). If you go looking for `MapManager`, `CombatCardSystem`, `EnemyManager`, `CardData`, the old dungeon generation, or the old contents of `scripts/core/{enemy,combat,cards,effects}` / `scripts/world/{rooms,dungeon}`, it no longer exists — don't try to "fix" references to it, and don't assume any design notes about it still apply.

**Removed in `feature/dote-resource-system`:** the AP (Action Points) system and STR/MAG/DEX combat stats built in `feature/tactical-grid-ap-controller` were fully removed in favor of the DotE-style resource/door-turn model above. `TurnManager.gd`, `ActionQueue.gd`, `WaitAction.gd`, `TurnButtonController.gd`, `ModifierStack.gd`, and `StatTypes.gd` no longer exist — don't go looking for AP-refill/per-actor-turn logic or STR/MAG/DEX modifier stacks, and don't assume the old blue/yellow AP-costed movement range still applies. `scripts/core/movement/` and `scripts/core/actions/` still exist but were reworked for free movement (see Tactical movement below) — they are not the AP-era code.

**Also removed, later in `feature/dote-resource-system`:** the original cell-by-cell BFS movement (`MapNavigationHelper.gd`, the `Highlight` `TileMapLayer`) is gone, replaced by room/corridor-graph movement (`RoomManager`/`RoomZone`, see Tactical movement below). `Door.gd`'s old Manhattan-adjacency-to-`player.grid_pos` check and `DoorTurnSystem.get_visited_cells()`/`register_door()` are gone too — don't go looking for per-cell walkability checks or door self-validation, movement/door-access is now zone-graph-based throughout.

## Commands

No build system, linter, test suite, CI, or export presets exist in this repo. Only real dev commands:

```bash
godot --path . --editor   # open in editor
godot --path .             # run the game
```

If asked to add tests/lint/CI, there is nothing existing to hook into — treat it as new infrastructure, not "run the existing suite."

## Architecture

**Autoloads** (project.godot `[autoload]`):
- `PlayerStats` (scripts/core/stats/PlayerStats.gd) — persistent player base HP, active (HP-only) upgrades, runtime `CharacterStats`; emits `stats_changed`/`player_died`. `register(stats)` binds a live `CharacterStats` node and re-applies base HP + upgrades onto it via `refresh_stats()`.
- `SaveManager` (scripts/managers/SaveManager.gd) — persists progression/upgrades/run cycle/slots/`selected_character_id` to `user://slot_<id>.cfg`. `apply_character_selection(id)` looks up `CharacterDatabase`, pushes base HP onto `PlayerStats`, and saves.
- `CurrencyManager` (scripts/managers/CurrencyManager.gd) — facade over `SaveManager.gold`, debounced persistence, emits `gold_changed`.
- `ResourceManager` (scripts/managers/ResourceManager.gd) — tracks the 4 DotE resources (`industry`/`food`/`science`/`dust`), emits `resource_changed(key, amount, delta)`. No persistence yet (resets per run); ticked by `DoorTurnSystem.open_room()`.
- `ThemeManager` (scripts/core/theme/ThemeManager.gd) — builds reusable `StyleBoxFlat`s for UI/menus.
- `SettingsManager` (scripts/managers/SettingsManager.gd) — persists UI SFX volume (click/hover), audio bus volumes (Master/Music/SFX/UI via `AudioServer`), video settings (window mode/resolution/vsync/FPS limit via `DisplayServer`/`Engine.max_fps`, applied automatically in `_ready()`) and gameplay screen-shake intensity to `user://settings.cfg`, emits `settings_changed`/`volume_changed`.
- `SteamManager` (scripts/network/SteamManager.gd) — Steam API init (AppID 480), Steam auth-ticket issuance/validation, `connected_clients`/`pending_clients` peer↔steam_id bookkeeping; owns a child `SteamLobbyManager` (scripts/network/SteamLobbyManager.gd, not an autoload) that handles lobby create/join/leave and `SteamMultiplayerPeer` wiring.
- `FPSOverlay` (scripts/ui/overlays/FPSOverlay.gd) — toggleable FPS counter overlay, driven by `SettingsManager.show_fps_overlay` (Video tab).

**`ManagerLocator`** (scripts/managers/ManagerLocator.gd) is the central indirection point: wraps autoload access (`get_save_manager`, `get_currency_manager`, `get_player_stats`, `get_settings_manager`, `get_steam_manager`, `get_resource_manager`) and group-based lookup for singletons that are *not* autoloads (`get_game_state_manager()` via `game_state_manager` group, `get_main_orchestrator()` via `main_orchestrator` group, `get_floating_text_manager()` via group, lazily instantiating on the scene root if absent). Fetch managers through this rather than raw autoload names or ad-hoc `get_tree().get_first_node_in_group()` calls.

**`Main` orchestrator** (`scenes/Main.tscn`, `scripts/managers/Main.gd`) — the project's `run/main_scene`. Owns four containers: `WorldContainer` (Node2D, hosts a `Main2d.tscn` instance during gameplay), `UIContainer` (CanvasLayer, hosts `MainMenu.tscn`/`WaitingRoom.tscn`), `HUDContainer` (plain Node, hosts a `HUD.tscn` instance during gameplay), `TransitionOverlay` (CanvasLayer, layer 200, a full-screen `ColorRect` faded via `MenuTransitionFX`). Public API — `show_main_menu()`, `start_gameplay()`, `go_to_waiting_room()`, `reload_gameplay()`, `return_to_main_menu()` — replaces all `get_tree().change_scene_to_file()`/`reload_current_scene()` calls project-wide; callers reach it via `ManagerLocator.get_main_orchestrator()` (never a raw node path), always null-check the result (it's null if a scene like `MainMenu.tscn`/`Main2d.tscn` is run standalone via the editor's "Play Scene", F6, instead of through `Main.tscn` via F5/"Play Project") and log via `QuestLogger` rather than crash. If `run/main_scene` in `project.godot` is ever hand-edited outside the Godot editor while the editor has the project open, the editor's in-memory main-scene setting is stale until the project is reloaded/reopened — restart the editor after such an edit.

**`GameStateManager`** (scripts/managers/GameStateManager.gd) — scene-instantiated (not an autoload) gameplay state machine: `State` enum ACTIVE/PAUSED/DEAD. Other systems call its `can_process_*` helpers to gate logic, and it emits `state_changed`/`pause_requested`/`resume_requested`/`death_entered`.

**`DoorTurnSystem`** (scripts/core/actions/DoorTurnSystem.gd) — scene-instantiated (not an autoload, one per `Main2d` instance) minimal DotE turn/room stub. Tracks `rooms: Dictionary` (room_id → `{cells, visited}`, keyed by "group_id" — see `RoomManager` below) and `current_turn`; `register_room()` sets it up, `is_room_visited(room_id)`/`get_room_cells(room_id)` are the read API. `open_room(room_id)` (called directly by `PlayerActionController`, not via a signal) marks the room visited, increments `current_turn`, emits `turn_advanced`/`room_revealed(room_id, cells)`, ticks `ResourceManager.add_all()` with placeholder per-door deltas, and emits `enemy_wave_requested(room_id)` — a log-only placeholder signal since no enemy system exists. `Door` (scripts/world/Door.gd, `Area2D`) is a standalone clickable node (`door_id`/`target_room_id`/`from_zone_id`/`cell`) that emits `door_clicked` on left-click — it does no adjacency validation itself; `PlayerActionController` checks `door.from_zone_id == player.current_zone_id` before opening. `Main2d.tscn` hand-places 4 (`DoorHub`/`DoorNorth`/`DoorEast`/`DoorVault`) as a working example, not a real dungeon generator.

**`Player`** (scripts/core/player/Player.gd) — `Node2D` actor: owns a `CharacterStats` child, a `current_zone_id: String` (authoritative position — which `RoomManager` zone the hero is in), and an `AnimatedSprite2D`. `configure(character_data)` (called before `add_child()`) stashes the selected `CharacterData` for `_ready()` to apply (`sprite_frames`); `set_zone(zone_id, center, tilemap)` sets `current_zone_id` + `global_position` + a derived `grid_pos` (debug/logging only, not used for movement/door logic anymore). `can_accept_input()` just checks `stats.is_alive()` — movement is free, no per-turn gating.

**Room-graph movement** (`scripts/world/RoomManager.gd` + `RoomZone.gd`, `scripts/core/movement/`) — `RoomManager` (`Node2D`, scene-instantiated per `Main2d` instance, group `"room_manager"`) owns the room/corridor graph: geometry (`zones: Dictionary`, zone_id → rect/cells/world `center_position`/`neighbors`/`group_id`), adjacency, and the clickable `RoomZone` (`Area2D`, scenes/RoomZone.tscn) child per zone. `is_zone_revealed(zone_id)` delegates to `DoorTurnSystem.is_room_visited()` — no duplicated visited state. `find_zone_path(from_id, to_id)` is a BFS over `neighbors` restricted to revealed zones — the connectivity gate for direct-click movement. `RoomZone` renders hover/selection feedback itself (`Polygon2D` fill + `Line2D` outline, `Highlight` enum NONE/CURRENT/REACHABLE/OPENABLE/BLOCKED) — there is no more painted BFS-reachable overlay. `GridUtils.gd` (cell↔world conversion against a `TileMapLayer`) is still used for door positioning and `Player.grid_pos`. `PlayerActionController.gd` (scripts/core/movement/) is purely signal-driven (`RoomZone.clicked/hovered/unhovered`, `Door.door_clicked` — no `_unhandled_input`, no raw mouse polling) and coordinates: click a revealed connected zone → glide there; click an unrevealed zone or its closed door → `DoorTurnSystem.open_room()` + `ResourceManager` tick + auto-glide in. Movement itself executes as `scripts/core/actions/MoveAction.gd`, a `BaseAction` subclass that tweens the `Player` through an `Array[Vector2]` of world-space waypoints (room/corridor centers) with a single continuous `Tween` — no per-cell steps, no AP cost, no turn consumption. Unrevealed rooms' cells are never painted onto `Floor` (see `FloorGenerator.fill_cells()`), so they stay invisible (basic fog-of-war) even though their `RoomZone` still exists for click detection.

**`Logger`** (scripts/core/utils/Logger.gd, `class_name QuestLogger`) — categorized/leveled logging (`Category`: GENERAL/COMBAT/CARDS/MAP/STATE/ACTIONS/SAVE/UI/CAMERA/NETWORK/DOOR; `Level`: DEBUG/INFO/WARN/ERROR), replacing raw `print()` calls project-wide. Use it for new diagnostics instead of `print()`.

**Multiplayer flow**: Main menu "Iniciar Partida" opens `NetworkModeSelect` (scenes/NetworkModeSelect.tscn) with Host/Join/Offline. Host creates a Steam lobby (`SteamLobbyManager.create_lobby`, Friends Only) then picks a save slot via `SaveSlotSelector` (script on `scenes/SlotSelection.tscn`, not its own scene); Join opens the Steam friends overlay and joins via `join_requested`/`lobby_joined`. Joining clients must pass Steam auth-ticket validation (mandatory-blocking, 15s timeout) before `SteamManager.connected_clients` counts them as real players. Both paths land in `scenes/WaitingRoom.tscn` before the host starts gameplay; Offline is unchanged in shape (`SlotSelection.tscn` → `CharacterSelection.tscn` → gameplay, no networking) but every transition now goes through the `Main` orchestrator (`ManagerLocator.get_main_orchestrator().start_gameplay()` / `.go_to_waiting_room()` / `.return_to_main_menu()`), not `change_scene_to_file()`.

**`Main2d.tscn` gameplay scene** (scripts/managers/Main2d.gd): instantiated by `Main.gd.start_gameplay()`/`reload_gameplay()` into `WorldContainer` (no longer a directly-run scene, and no longer owns a static `HUD.tscn` child — HUD is instantiated separately into `Main.gd`'s `HUDContainer`). On `_ready()` it resolves `active_character_id` from `SaveManager.get_selected_character_id()`, ensures a `GameStateManager` child exists, sets up a `DoorTurnSystem`, builds `RoomManager` from a hand-defined `LAYOUT` const (9 zones: 5 rooms + 4 corridors, grouped into 5 `DoorTurnSystem` reveal groups "start"/"hub"/"north"/"east"/"vault"), registers the 4 `Doors/*` children against it, spawns `Player.tscn` at the `"start_room"` zone's center (`configure(character_data)` + `set_zone()`), wires `PlayerActionController`, and connects pause/death overlay signals. Owns `Floor` (scripts/world/FloorGenerator.gd, a `TileMapLayer`; `fill_cells(cells)` paints a room's tiles on reveal, `auto_fill_full_map` (default off) is a legacy/debug full-map-fill toggle, `resources/tileset/placeholder_tileset.tres`) and `RoomManager` (a `Node2D`, spawns one `RoomZone` child per graph zone — no more separate `Highlight` `TileMapLayer`, that node/tileset reference was removed from the scene). `Main2dDeathHandler.gd` presents the death overlay/run summary (unchanged, pure presentation helper).

**HUD** (`scenes/HUD.tscn`, `scripts/ui/hud/HUDController.gd`): HP bar/label plus 4 resource rows (Industria/Comida/Ciencia/Polvo, each icon+label via `scripts/ui/hud/StatIcon.gd`'s vector-drawn icons) — no AP, no "Pasar Turno" button. `scripts/ui/hud/StatPanelUI.gd` formats `update_hp()`/`update_resource(key, amount)`; `HUDController` binds `PlayerStats.stats_changed` (HP) and `ResourceManager.resource_changed` (the 4 resources) directly, no turn-button controller. Instantiated by `Main.gd` into `HUDContainer` (a sibling of `WorldContainer`, not a child of `Main2d.tscn`) — `HUDController` is fully self-wiring (autoload/group lookups only), so its own host in the tree doesn't matter. `HUDController` still adds itself to the `"hud"` group and exposes `show_simple_tooltip`/`hide_simple_tooltip` + a `StatTooltip` node — these are load-bearing for `StorePanel.gd` (pause-menu HP-upgrade store, unrelated to the old card system), not just HUD self-use.

## When picking up gameplay work here

`Main2d.tscn` has a 9-zone room/corridor graph (`LAYOUT` in `Main2d.gd`, built by `RoomManager`), a spawned hero positioned by zone (`Player.current_zone_id`), and click-a-connected-zone-to-glide-there movement (`scripts/world/RoomManager.gd`/`RoomZone.gd`, `scripts/core/movement/PlayerActionController.gd`, `scripts/core/actions/MoveAction.gd`) — see `feature/dote-resource-system`. A minimal `DoorTurnSystem` (4 hand-placed `Door` nodes under `Doors/`) advances the global turn and ticks `ResourceManager` on open; there is still no real dungeon generation, targeting, combat, or enemies (`enemy_wave_requested` is a log-only placeholder signal, no `EnemyManager` exists). Before building a new `BaseAction` subclass (attack, ability, etc.), look at `MoveAction.gd` as the reference implementation: `can_execute()`/`execute()`/`finish()`, no AP or turn-consumption bookkeeping needed — movement and any future actions execute immediately, they don't go through a turn queue. The gameplay scene is never run standalone (F6 in the editor) once the orchestrator exists — it's instantiated by `Main.gd` into `WorldContainer`; run the project (F5) via `scenes/Main.tscn` instead, or `ManagerLocator.get_main_orchestrator()` returns null and any scene-flow button (Retry/Exit/Start/Leave) logs an error instead of working. Gameplay input (RoomZone/Door clicks) is entirely `Area2D.input_event`-driven — never read raw mouse input via `_unhandled_input`/`_input` in gameplay nodes and call `set_input_as_handled()` on it, since that runs *before* Area2D physics-picking in Godot 4 and silently swallows the click before it reaches any zone/door (this was a real bug in the old `PlayerActionController`).
