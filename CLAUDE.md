## Project overview

QUEST: 2D tactical/roguelite game built in Godot 4.6, GDScript only (no C#/.NET), GL Compatibility renderer. A menu/character-select/save-slot shell, run under a `Main.tscn` scene orchestrator, around a *Dungeon of the Endless*-style gameplay scaffold (`Main2d.tscn`): pick a hero, spawn into a room/corridor graph (`RoomManager`) over a multi-room `TileMapLayer` floor with real HP (no combat stats), click a revealed room/corridor connected to the hero's current one to glide straight there, and a global turn that advances only when a door is opened — ticking a 4-resource economy (industry/food/science/dust) and revealing the next room+corridor (basic fog-of-war). A revealed room can be spent-Dust "energized" (`RoomPowerSystem`) to unlock 3 build slots for `Module`s (Major Generators feeding bonus resources on door-open, Minor Turret/Trap defenses); the run's win condition is grabbing `El Nexo` in the start room, surviving a door-blocked `ExtractionManager` extraction phase (periodic enemy waves in still-dark rooms) while carrying it 25% slower, and reaching the designated exit room. Basic `Enemy` entities (Swarm/Sapper/Hunter) spawn in dark (unpowered) rooms via `EnemyManager`, both on every door-open and on the extraction timer, and hop across the same revealed-only `RoomManager` graph the hero uses. Supports Steam multiplayer (Host/Join via GodotSteam lobbies with auth-ticket validation) alongside the offline single-player flow.

## Commands

No build system, linter, CI, or export presets exist in this repo. Only real dev commands:

```bash
godot --path . --editor   # open in editor
godot --path .             # run the game
```

Headless checks (Godot 4.6.2 lives at `E:\Descargas\Godot_v4.6.2-stable_win64.exe\Godot_v4.6.2-stable_win64_console.exe` on the dev machine):

```bash
godot --headless --path . res://scenes/Main2d.tscn --quit-after 90   # load a scene, watch for SCRIPT ERROR
godot --headless --path . --script res://tests/test_map_generator.gd  # 1000 generated layouts valid + deterministic
godot --headless --path . --script res://tests/test_map_flow.gd       # boots Main2d, opens every door, checks dust/fog
godot --headless --path . --script res://tests/test_corridor_picking.gd  # physics-picks every corridor/door/room-edge cell, 25 seed x floor maps + fallback
godot --headless --path . --script res://tests/test_hud_ui.gd         # HP-bar thresholds, upgrade curve/purchases, BuildingMenu, over a live Main2d + HUD
python -m gdtoolkit.parser <files.gd>                                # "gdparse" (not on PATH on the dev machine)
godot --headless --path . --editor --quit                            # rescan class cache if a new class_name "can't be found"
```

`tests/` are plain `extends SceneTree` scripts (exit code 0/1), no framework. Right after adding a new `class_name`, the first `--script` run may fail with `Could not find type` / `Could not resolve external class member` — reindex with `--editor --quit`. In `--script` mode autoload identifiers aren't registered, so UI scripts log `Identifier not found: ThemeManager` — noise, not a real failure (autoload *instances* exist: tests use `root.get_node("ResourceManager")`). HUD scripts that tests load reach the static helper via `const ThemeStyles = preload("res://scripts/core/theme/ThemeManager.gd")` instead — do the same in new HUD code. Expected headless noise: GodotSteam/Steam not running, and `ObjectDB instances leaked` / `1 resources still in use at exit` when cut by `--quit-after` (preexisting). The old cursor-UID and `OptionsMenu.tscn` UID errors were fixed in session 4 (the custom cursor asset had been deleted; the project now uses the system cursor).

If asked to add tests, add another `tests/*.gd` SceneTree script in the same style; lint/CI still don't exist (new infrastructure).

## Architecture

**Autoloads** (project.godot `[autoload]`):
- `PlayerStats` (scripts/core/stats/PlayerStats.gd) — persistent player base HP, active (HP-only) upgrades, runtime `CharacterStats`; emits `stats_changed`/`player_died`. `register(stats)` binds a live `CharacterStats` node and re-applies base HP + upgrades onto it via `refresh_stats()`. Two upgrade tracks, both applied only through here: meta Oro upgrades (`apply_upgrade`, `StorePanel` in the pause menu, persisted) and in-run Ciencia upgrades (`run_upgrade_levels` hp/damage/attack_speed, `buy_run_upgrade(key)`/`get_run_upgrade_preview(key)`/`get_hero_level()`, `run_upgrades_changed`; config `UpgradeConfig`; re-applied on every `register` so they survive floors, reset by `Main._begin_new_run()`, not saved).
- `SaveManager` (scripts/managers/SaveManager.gd) — persists progression/upgrades/run cycle/slots/`selected_character_id` to `user://slot_<id>.cfg`. `apply_character_selection(id)` looks up `CharacterDatabase`, pushes base HP onto `PlayerStats`, and saves.
- `CurrencyManager` (scripts/managers/CurrencyManager.gd) — facade over `SaveManager.gold`, debounced persistence, emits `gold_changed`.
- `ResourceManager` (scripts/managers/ResourceManager.gd) — tracks the 4 DotE resources (`industry`/`food`/`science`/`dust`), emits `resource_changed(key, amount, delta)`. `spend_resource(key, amount) -> bool` (clone of `CurrencyManager.spend_gold`'s pattern) refuses and returns `false` on insufficient funds instead of silently clamping — `RoomPowerSystem`/`ModuleBuildSystem` use this, not `add_resource` with a negative delta. No persistence yet (resets per run); ticked by `DoorTurnSystem.open_room()`. `get_turn_yield(key)` = base + generator bonus (what `process_turn_production()` pays, shown as `+N` in the HUD); `production_changed` fires when a `GeneratorModule` is configured/destroyed.
- `ThemeManager` (scripts/core/theme/ThemeManager.gd) — builds reusable `StyleBoxFlat`s for UI/menus.
- `SettingsManager` (scripts/managers/SettingsManager.gd) — persists UI SFX volume (click/hover), audio bus volumes (Master/Music/SFX/UI via `AudioServer`), video settings (window mode/resolution/vsync/FPS limit via `DisplayServer`/`Engine.max_fps`, applied automatically in `_ready()`) and gameplay screen-shake intensity to `user://settings.cfg`, emits `settings_changed`/`volume_changed`.
- `SteamManager` (scripts/network/SteamManager.gd) — Steam API init (AppID 480), Steam auth-ticket issuance/validation, `connected_clients`/`pending_clients` peer↔steam_id bookkeeping; owns a child `SteamLobbyManager` (scripts/network/SteamLobbyManager.gd, not an autoload) that handles lobby create/join/leave and `SteamMultiplayerPeer` wiring.
- `FPSOverlay` (scripts/ui/overlays/FPSOverlay.gd) — toggleable FPS counter overlay, driven by `SettingsManager.show_fps_overlay` (Video tab).

**`ManagerLocator`** (scripts/managers/ManagerLocator.gd) is the central indirection point: wraps autoload access (`get_save_manager`, `get_currency_manager`, `get_player_stats`, `get_settings_manager`, `get_steam_manager`, `get_resource_manager`) and group-based lookup for singletons that are *not* autoloads (`get_game_state_manager()` via `game_state_manager` group, `get_main_orchestrator()` via `main_orchestrator` group, `get_room_manager()` via `room_manager` group, `get_player()` via `player` group, `get_room_power_system()`/`get_module_build_system()`/`get_extraction_manager()`/`get_enemy_manager()`/`get_floor_manager()` via their like-named groups, `get_floating_text_manager()` via group, lazily instantiating on the scene root if absent). Fetch managers through this rather than raw autoload names or ad-hoc `get_tree().get_first_node_in_group()` calls.

**`Main` orchestrator** (`scenes/Main.tscn`, `scripts/managers/Main.gd`) — the project's `run/main_scene`. Owns four containers: `WorldContainer` (Node2D, hosts a `Main2d.tscn` instance during gameplay), `UIContainer` (CanvasLayer, hosts `MainMenu.tscn`/`WaitingRoom.tscn`), `HUDContainer` (plain Node, hosts a `HUD.tscn` instance during gameplay), `TransitionOverlay` (CanvasLayer, layer 200, a full-screen `ColorRect` faded via `MenuTransitionFX`). Public API — `show_main_menu()`, `start_gameplay()`, `go_to_waiting_room()`, `reload_gameplay()` (Retry = new run from floor 1), `advance_floor()` (same run, `current_floor += 1`, resources kept), `return_to_main_menu()` — `start_gameplay()`/`reload_gameplay()` call `_begin_new_run()` (floor 1 + `ResourceManager.reset_resources()`; before this nothing ever reset resources, so runs started at 0 dust) — replaces all `get_tree().change_scene_to_file()`/`reload_current_scene()` calls project-wide; callers reach it via `ManagerLocator.get_main_orchestrator()` (never a raw node path), always null-check the result (it's null if a scene like `MainMenu.tscn`/`Main2d.tscn` is run standalone via the editor's "Play Scene", F6, instead of through `Main.tscn` via F5/"Play Project") and log via `QuestLogger` rather than crash. If `run/main_scene` in `project.godot` is ever hand-edited outside the Godot editor while the editor has the project open, the editor's in-memory main-scene setting is stale until the project is reloaded/reopened — restart the editor after such an edit.

**`GameStateManager`** (scripts/managers/GameStateManager.gd) — scene-instantiated (not an autoload) gameplay state machine: `State` enum ACTIVE/PAUSED/DEAD/VICTORY. Other systems call its `can_process_*` helpers to gate logic, and it emits `state_changed`/`pause_requested`/`resume_requested`/`death_entered`/`victory_entered`. `request_victory()` (mirrors `request_death()`) is called by `ExtractionManager.declare_victory()`, not by the state machine itself — it's a terminal, tree-pausing state like DEAD, but it isn't the same thing as the `ExtractionManager.Phase` flag below (that one gates door-opening/spawns, not process-freezing).

**`DoorTurnSystem`** (scripts/core/actions/DoorTurnSystem.gd) — scene-instantiated (not an autoload, one per `Main2d` instance) minimal DotE turn/room stub. Tracks `rooms: Dictionary` (room_id → `{cells, visited}`, keyed by "group_id" — see `RoomManager` below) and `current_turn`; `register_room()` sets it up, `is_room_visited(room_id)`/`get_room_cells(room_id)` are the read API. `open_room(room_id)` (called directly by `PlayerActionController`, not via a signal) marks the room visited, calls `advance_turn(room_id)` (the only place `current_turn` increments; emits `turn_advanced` + `door_opened(target_room_id)`), emits `room_revealed(room_id, cells)`, ticks `ResourceManager.add_all()` with flat per-door deltas *plus* a second `add_all()` summing every built Generator `Module`'s bonus (`RoomManager.get_all_modules()`), then calls `EnemyManager.spawn_enemies_in_room()` on a random unpowered revealed room before emitting `enemy_wave_requested(room_id)` (signal kept for any future listener, no longer the only consumer). `Door` (scripts/world/Door.gd, `Area2D`) is a standalone clickable node (`door_id`/`target_room_id`/`from_zone_id`/`cell`) that emits `door_clicked` on left-click — it does no adjacency validation itself (`get_target_room_for(zone_id)` returns the opposite of `room_a_id`/`room_b_id`, or "" if not adjacent; `disable_door()` sets `is_open`, disables its collision shape, fades to alpha 0.3); `PlayerActionController` checks `door.get_target_room_for(player.current_zone_id) != ""` and `ExtractionManager.can_open_doors()` before opening. `Main2d` spawns one `Door` per `CorridorData` at runtime (`door_id` = corridor id, `target_room_id` = `room_b`'s group, `from_zone_id` = `room_a`, `cell` = `door_cell`); there are no hand-placed doors in `Main2d.tscn` anymore.

**Room powering & modules** (`scripts/world/RoomZone.gd`, `scripts/core/actions/RoomPowerSystem.gd`, `scripts/world/{Module,BuildingSlot,EnergyButton}.gd`) — a revealed room-kind `RoomZone` shows an `EnergyButton` child ("Energizar (10)"); clicking it calls `RoomZone.try_power_up()`, which spends `POWER_COST` (10) dust via `ResourceManager.spend_resource()` (floating "Polvo insuficiente" on failure), calls `set_powered(true)` and emits `powered_up` → bubbled through `RoomManager.room_powered` → `RoomPowerSystem` (scene-instantiated per `Main2d`, group `"room_power_system"`, now only a re-broadcaster/logger via `room_energized`). `set_powered` hides the button and recolors the zone gold and spawns 3 `BuildingSlot` children into the `BuildingSlots` container (1 `BuildingSlot.SlotType.MAJOR` at zone center + 2 `MINOR`, fixed local offsets); slot clicks are ignored unless the parent zone's `can_build()` is true. Clicking an empty `BuildingSlot` emits `slot_clicked` → bubbled through `RoomManager.slot_clicked` → `ModuleBuildSystem` (group `"module_build_system"`) only routes it to `HUDController.open_building_menu()` → `BuildingMenu` (scenes/ui/BuildingMenu.tscn, scripts/ui/BuildingMenu.gd, child of the HUD's `Control`), which lists `Module.CATALOG` entries matching the slot's type, spends Industria via `ResourceManager.spend_resource()` (shake + floating text on failure, menu stays open), and calls `BuildingSlot.build()` (loads the catalog's `scene` path); right-click/outside-click closes it. `Module.CATALOG` (keyed by `ModuleType` GENERATOR_INDUSTRY/GENERATOR_FOOD/GENERATOR_SCIENCE/TURRET/TRAP, each generator yields only its own resource via `Module.generator_yield()`) holds cost + effect numbers; `Module` owns its own small HP block (`take_damage()`/`die()`/`module_destroyed` signal — `die()` sets `is_active=false`, emits, `queue_free()`; `BuildingSlot` listens and frees itself, mirrors `CharacterStats.take_damage`'s clamp shape, not a shared base class) — Generators are `GeneratorModule` (scenes/world/GeneratorModule.tscn, group `"generators"`, `resource_type`/`yield_amount` from the catalog) summed by `ResourceManager._calculate_module_bonus()` inside `process_turn_production()` (DoorTurnSystem no longer adds a separate bonus); Turrets are `TurretModule` (scenes/world/TurretModule.tscn) with a `DetectionZone` `Area2D` (mask layer 2 = `Enemy`, which now sits on collision layer 2 and in group `"enemies"`) and a `FireTimer` hitting `current_targets[0]` for `damage` (15) every `fire_rate` (1.0s), a Trap module is a passive marker an `Enemy` checks for on room-arrival (see Enemies below).

**Nexo & extraction phase** (`scripts/world/{Nexo,NexoController}.gd`, `scripts/managers/ExtractionManager.gd`) — `El Nexo` (`Area2D`) sits at the layout's start room (`RoomManager.get_start_zone_id()`, `"start_room"` only in the fallback)'s center; clicking it only works while the hero is physically in `start_room` (`NexoController` gate), then calls `Player.pick_up_nexo()` (sets `is_carrying_nexo`, read by `PlayerActionController._run_move()` to glide at 75% `MoveAction.DEFAULT_SPEED_PX`) and `ExtractionManager.start_extraction()`. `ExtractionManager` (scene-instantiated, group `"extraction_manager"`) is an orthogonal run-flow flag (`enum Phase {EXPLORATION, EXTRACTION}`), deliberately *not* folded into `GameStateManager.State` — extraction doesn't freeze input/turns, it only makes `can_open_doors()` return `false` (checked in `PlayerActionController._open_group()`) and starts a 5s-repeating `Timer` that spawns 1 enemy in every unpowered revealed room (`RoomManager.get_unpowered_revealed_room_group_ids()`). Walking the nexo-carrying hero into the layout's `is_exit_room` zone (the room farthest from the start in generated maps, `vault_room` in the fallback; `RoomData.is_exit`) triggers `ExtractionManager.declare_victory()` → `GameStateManager.request_victory()` → `Main2dVictoryHandler` (1:1 structural clone of `Main2dDeathHandler`) shows `VictoryOverlay`.

**Enemies** (`scripts/entities/Enemy.gd`, `scripts/core/actions/EnemyMoveAction.gd`, `scripts/managers/EnemyManager.gd`) — Invasions are rolled by `EnemyManager._on_turn_advanced` (connected to `DoorTurnSystem.turn_advanced`): P = min(0.85, 0.05 + dark_rooms*0.08 + turn*0.015) via `RoomManager.get_dark_rooms()`, count = 1 + turn/5, emits `invasion_triggered(rooms, count)` which it also consumes to spawn (`DoorTurnSystem.open_room()` no longer spawns directly). `EnemyManager` (scene-instantiated per `Main2d`, group `"enemy_manager"`, *not* an autoload — same per-run-state reasoning as `DoorTurnSystem`) spawns weighted-random `Enemy.Variant` (60% SWARM/25% SAPPER/15% HUNTER) into a room and tracks them in `_enemies`. Enemies are `CharacterBody2D` (`Enemy.tscn`, collision layers 0, `setup(start_position)` + `configure(variant, zone_id)`) added under a dedicated `Enemies` `Node2D` child of `EnemyManager`; `_on_invasion_triggered` picks a random spawn room per enemy and spawns at `room.center_position`. `HUDController` connects to `invasion_triggered` and pulses a red `InvasionFlash` `ColorRect` (`trigger_invasion_alert()`). `Enemy` has no real pathfinding: a per-enemy `AiTimer` periodically calls `RoomManager.find_zone_path()` (the same revealed-only BFS `PlayerActionController` uses) and glides the full path via `EnemyMoveAction` (a `BaseAction` clone of `MoveAction` that re-reads `Enemy.current_speed()` per leg, so a Trap's `apply_slow()` takes effect mid-transit, and sets `Enemy.current_zone_id` on arrival). SWARM always beelines the hero's zone; HUNTER only moves once `Player.is_carrying_nexo` is true (otherwise idles); SAPPER stays in-room damaging the first `Module` it finds each tick (`RoomManager.get_modules_in_group()`) and only moves once its room has none left. Every variant has a `State {MOVING, ATTACKING}`: `EnemyMoveAction` calls `Enemy.on_zone_entered()` on each zone center reached; `scan_room_for_modules()` finds an active `Module` → `target_module`, ATTACKING, `AttackTimer` fires `_perform_attack()` (`attack_damage`, SAPPER uses `damage_per_tick`) until the module dies, then `_resume_moving()`. `Enemy` owns the same small self-contained HP block pattern as `Module` (`take_damage()`/`died` signal).

**Hero↔enemy combat** (`scripts/core/combat/{HitboxComponent,HurtboxComponent}.gd`, added in `session/opus-2026-09-27`) — DotE-style auto-combat, no input. `HurtboxComponent` (`Area2D`, monitorable only) owns no HP, it just emits `hurt(amount)`; the owner connects it in `_ready()` (`Player._on_hurt` → `CharacterStats.take_damage`, `Enemy.take_damage`). `HitboxComponent` (`Area2D`, monitoring only) damages every overlapping `HurtboxComponent` every `hit_interval` via an internal `Timer`; `configure(damage, interval)` sets it at runtime. Targeting is purely physics layers (`project.godot [layer_names]`): layer 2 `enemy_body` (Turret `DetectionZone`), layer 3 `player_hurtbox` (value 4), layer 4 `enemy_hurtbox` (value 8). Hero `Hitbox` (radius 160 ≈ half a 5×5 room, AoE) masks 8, damage/interval from `CharacterStats.attack_damage`/`attack_interval` (base = `CharacterData.attack_damage`/`attack_interval`, `@export_group("Combat")`, defaults 3/1.0s, plus in-run upgrades; `CharacterStats.attack_changed` → `HitboxComponent.configure`, wired in `Player._ready` before `PlayerStats.register`); `Enemy` `Hitbox` (radius 24, contact) masks 4, damage from `VARIANT_CONFIG[*]["contact_damage"]`. The death flow (`CharacterStats.died` → `PlayerStats.player_died` → `Main2d._on_player_died`) is now reachable. Turrets still use their own `DetectionZone`/`take_damage` path, not these components. `HitboxComponent` also spawns damage numbers on `hit_landed` via `FloatingTextManager` (`@export_group("Feedback")`: `show_damage_numbers`/`damage_number_color`, red on enemies).

**Floor progression** (`scripts/core/floors/FloorConfig.gd`, `resources/floors/default_floor_config.tres`, `scripts/managers/FloorManager.gd`) — the run's floor counter lives on the `Main` orchestrator (`current_floor`), because `Main2d` is freed between floors. `Main2d._setup_floor_manager()` creates a per-floor `FloorManager` (group `"floor_manager"`, scene-instantiated) with that index; it's a facade over the `FloorConfig` Resource (linear growth in `floor_index - 1`: enemy HP/damage multipliers, invasion chance bonus/extra enemies, extraction wave interval, `max_floors` = 5, `dust_bonus_on_descend` added in `setup()` on floor 2+). `EnemyManager.setup(..., floor_manager)` applies it in `_on_turn_advanced` and passes multipliers to `Enemy.configure(variant, zone, hp_mult, dmg_mult)`; `ExtractionManager.setup(..., spawn_interval)` takes `floor_manager.extraction_interval()`. `ExtractionManager.victory_declared` → `FloorManager.complete_floor()` → `floor_completed(floor_index)` → `Main2d._on_floor_completed` (runs before `victory_entered`) shows `VictoryOverlay/.../NextFloorButton` ("Descender al piso N") unless `is_final_floor()`; the button calls `Main.advance_floor()`. HUD `Control/FloorLabel` shows `Piso N/M` (read once in `_ready()` — a new floor is a new HUD). A different generated map every floor (more rooms/branching per floor); hero HP resets each floor (new `Player` → `PlayerStats.register` → `refresh_stats`).

**`Player`** (scripts/core/player/Player.gd) — `Node2D` actor: owns a `CharacterStats` child, a `current_zone_id: String` (authoritative position — which `RoomManager` zone the hero is in), and an `AnimatedSprite2D`. `configure(character_data)` (called before `add_child()`) stashes the selected `CharacterData` for `_ready()` to apply (`sprite_frames`); `set_zone(zone_id, center, tilemap)` sets `current_zone_id` + `global_position` + a derived `grid_pos` (debug/logging only, not used for movement/door logic anymore). `can_accept_input()` just checks `stats.is_alive()` — movement is free, no per-turn gating.

**Map generation** (`scripts/world/map/{RoomData,CorridorData,MapLayout,MapGenerator}.gd`, `resources/maps/fallback_layout.tres`) — `MapLayout` (Resource) = `rooms: Array[RoomData]` (`id`, `kind`, cell `pos`/`size`, `neighbors`, `is_start`/`is_exit`/`is_vault`) + `corridors: Array[CorridorData]` (corridor *entities*: `room_a` = door side, `room_b`, 1-cell-wide rect, `door_cell` against `room_a`'s wall, *outside* `get_rect()`; `get_zone_rect()` = rect + door cell is what the corridor `RoomZone` is built from, so all 4 visible tiles stay clickable after `disable_door()`) + `map_seed`; `validate()` returns broken invariants (1 start, ≥1 exit, exactly one entry corridor per non-start room, no overlapping cells incl. door cells, all rooms reachable). `MapGenerator.generate(seed, room_count, branch_chance)` is deterministic (own `RandomNumberGenerator`, never global `shuffle()`): rooms on a slot grid (`SLOT_PITCH` 9 cells, rooms ≤5×5 centered in the slot → can't overlap), each new room hangs off the newest (or, with `branch_chance`, a random earlier) room via a straight corridor → always a tree; exit = farthest room from start, vault = deepest remaining dead end (data flag only). Tree-only is deliberate: a reveal group = one room + its single entry corridor. `Main2d._build_map_layout()` uses `FloorManager.map_seed` (= `hash([Main.run_seed, floor])`, `run_seed` re-rolled per run), `room_count()`/`branch_chance()` (from `FloorConfig` "Map" group), falls back to `FALLBACK_LAYOUT` when `force_fallback_layout` (export, debug) is on or `validate()` fails. `RoomManager.build_from_map()`: zone graph `room_a ↔ corridor ↔ room_b`, group id = room id, group zones = [entry corridor, room]; start group registered visited. **Discovery dust:** `DoorTurnSystem.room_revealed` → `FloorManager.on_room_discovered()` adds `FloorConfig.discovery_dust(floor)` dust on every discovery, invasion or not ("Discovery" group, 2 + 0.5/floor; energizing still costs 10).

**Room lighting & exit hint** (`scripts/world/{RoomLight,ExitIndicator}.gd`, `scripts/world/map/MapVisualConfig.gd`, `resources/maps/map_visual_config.tres`) — `MapVisualConfig` (Resource, exported as `RoomManager.visual_config`) holds lighting colors/timings and `exit_hint_mode` (`enum ExitHintMode {ALWAYS, ON_DISCOVERY, ON_CRYSTAL}`, default `ON_DISCOVERY` since session 5 — the `.tres` omits the line because it equals the script default; its setter calls `emit_changed()`). Every room-kind `RoomZone` gets a `RoomLight` child (`RoomZone.attach_light()`, drawn under Fill/EnergyButton/slots, hidden with fog): dark = overlay pulsing dark↔blood-red (danger — dark rooms are the enemy spawn pool), gold outline while `dust >= RoomZone.POWER_COST` (`ResourceManager.resource_changed`), powered = tween overlay out + warm `PointLight2D` (code-generated radial `GradientTexture2D`) in. It reacts only to the new `RoomZone.power_changed(zone_id, powered)` signal (emitted by `set_powered` on any change; `powered_up` is still the player-paid-only signal). `ExitIndicator` (scene-instantiated per `Main2d`, group `"exit_indicator"`, `ManagerLocator.get_exit_indicator()`) puts a marker over `RoomManager.get_exit_zone_id()` (z 50, *not* a `RoomZone` child, so it shows through fog) and a screen-edge arrow on its own `CanvasLayer` (layer 5 — kept out of `HUD.tscn` so it lives/dies with the floor). Visible per mode (`ON_DISCOVERY` = exit revealed; `ON_CRYSTAL` = only while carrying), and always while carrying the Nexo, then recolored gold with a stronger pulse. State updates on `MapVisualConfig.changed`, `DoorTurnSystem.room_revealed`, `ExtractionManager.phase_changed` (EXTRACTION == carrying the Nexo); `_process` only positions the arrow (`ExitIndicator.edge_point()`), and only while the hint is visible. Change the mode in the `.tres` Inspector (permanent), on `Main2d.tscn`'s `RoomManager.visual_config` (per scene), or at runtime by assigning `visual_config.exit_hint_mode`.

**Room-graph movement** (`scripts/world/RoomManager.gd` + `RoomZone.gd`, `scripts/core/movement/`) — `RoomManager` (`Node2D`, scene-instantiated per `Main2d` instance, group `"room_manager"`) owns the room/corridor graph: geometry (`zones: Dictionary`, zone_id → rect/cells/world `center_position`/`neighbors`/`group_id`), adjacency, and the clickable `RoomZone` (`Area2D`, scenes/RoomZone.tscn) child per zone. `is_zone_revealed(zone_id)` delegates to `DoorTurnSystem.is_room_visited()` — no duplicated visited state. `find_zone_path(from_id, to_id)` is a BFS over `neighbors` restricted to revealed zones — the connectivity gate for direct-click movement. `RoomZone` renders hover/selection feedback itself (`Polygon2D` fill + `Line2D` outline, `Highlight` enum NONE/CURRENT/REACHABLE/OPENABLE/BLOCKED) — there is no more painted BFS-reachable overlay. `GridUtils.gd` (cell↔world conversion against a `TileMapLayer`) is still used for door positioning and `Player.grid_pos`. `PlayerActionController.gd` (scripts/core/movement/) is purely signal-driven (`RoomZone.clicked/hovered/unhovered`, `Door.door_clicked` — no `_unhandled_input`, no raw mouse polling) and coordinates: click a revealed connected zone → glide there; click a closed door (unrevealed zones are hidden + non-pickable via `RoomZone.set_visibility()`, revealed only through `RoomManager.reveal_room()`) → `DoorTurnSystem.open_room()` + `ResourceManager` tick + auto-glide in. Movement itself executes as `scripts/core/actions/MoveAction.gd`, a `BaseAction` subclass that tweens the `Player` through an `Array[Vector2]` of world-space waypoints (room/corridor centers) with a single continuous `Tween` — no per-cell steps, no AP cost, no turn consumption. Unrevealed rooms' cells are never painted onto `Floor` (see `FloorGenerator.fill_cells()`), so they stay invisible (basic fog-of-war) even though their `RoomZone` still exists for click detection. **Revealed vs visible (M2):** *revealed/discovered* (`RoomManager.is_zone_revealed`/`is_group_revealed`, backed by `DoorTurnSystem.rooms[group].visited`) gates gameplay (movement, dark rooms, enemy pathing); *visible* (`RoomManager.is_zone_visible`, derived, currently == revealed) decides what is drawn. The only presentation path is `RoomManager.apply_zone_visibility()`/`on_group_revealed()`/`refresh_visibility()`, which pushes `RoomZone.set_shown()` and `FloorGenerator.fill_cells()` — `RoomZone._shown` and the painted tiles are render state, never queried as truth (`validate_visibility()` checks they agree). Not verified in the editor yet (see `HANDOFF_ROOM_CORE_M2.md`).

**`Logger`** (scripts/core/utils/Logger.gd, `class_name QuestLogger`) — categorized/leveled logging (`Category`: GENERAL/COMBAT/CARDS/MAP/STATE/ACTIONS/SAVE/UI/CAMERA/NETWORK/DOOR; `Level`: DEBUG/INFO/WARN/ERROR), replacing raw `print()` calls project-wide. Use it for new diagnostics instead of `print()`.

**Multiplayer flow**: Main menu "Iniciar Partida" opens `NetworkModeSelect` (scenes/NetworkModeSelect.tscn) with Host/Join/Offline. Host creates a Steam lobby (`SteamLobbyManager.create_lobby`, Friends Only) then picks a save slot via `SaveSlotSelector` (script on `scenes/SlotSelection.tscn`, not its own scene); Join opens the Steam friends overlay and joins via `join_requested`/`lobby_joined`. Joining clients must pass Steam auth-ticket validation (mandatory-blocking, 15s timeout) before `SteamManager.connected_clients` counts them as real players. Both paths land in `scenes/WaitingRoom.tscn` before the host starts gameplay; Offline is unchanged in shape (`SlotSelection.tscn` → `CharacterSelection.tscn` → gameplay, no networking) but every transition now goes through the `Main` orchestrator (`ManagerLocator.get_main_orchestrator().start_gameplay()` / `.go_to_waiting_room()` / `.return_to_main_menu()`), not `change_scene_to_file()`.

**`Main2d.tscn` gameplay scene** (scripts/managers/Main2d.gd): instantiated by `Main.gd.start_gameplay()`/`reload_gameplay()` into `WorldContainer` (no longer a directly-run scene, and no longer owns a static `HUD.tscn` child — HUD is instantiated separately into `Main.gd`'s `HUDContainer`). On `_ready()` it resolves `active_character_id` from `SaveManager.get_selected_character_id()`, ensures a `GameStateManager` child exists, sets up a `DoorTurnSystem`, sets up `FloorManager` first, builds `RoomManager` from a per-floor `MapLayout` (see Map generation), registers every group with `DoorTurnSystem`, spawns one `Door` per corridor under `Doors`, spawns `Player.tscn` at `RoomManager.get_start_zone_id()`'s center (`configure(character_data)` + `set_zone()`), wires `PlayerActionController`, and connects pause/death overlay signals. Owns `Floor` (scripts/world/FloorGenerator.gd, a `TileMapLayer`; `fill_cells(cells)` paints a room's tiles on reveal, `auto_fill_full_map` (default off) is a legacy/debug full-map-fill toggle, `resources/tileset/placeholder_tileset.tres`) and `RoomManager` (a `Node2D`, spawns one `RoomZone` child per graph zone — no more separate `Highlight` `TileMapLayer`, that node/tileset reference was removed from the scene). `Main2dDeathHandler.gd` presents the death overlay/run summary (unchanged, pure presentation helper).

**HUD** (`scenes/HUD.tscn`, `scripts/ui/hud/HUDController.gd`), layout (all anchors/containers): top-left `TopLeft` = resource bar (Industria/Comida/Ciencia/Polvo: `StatIcon` vector icon + amount + green `+N` per-turn gain, `StatPanelUI.update_resource()`/`update_gain()`; `update_hp()` kept as a no-op) + `FloorLabel`; top-right `Portraits` = one `HeroPortrait` per hero (`HUDController.add_hero_portrait(stats, data)`, built in code; `CharacterData.portrait` or initial-circle placeholder + number-less HP bar tweened/colored via `HealthBarStyle`, flash on damage); bottom-right minimap; `CharacterPopup` (code-built modal child of `HUD/Control`: veil/X/Esc close — its `_input` consumes Esc before `Main2d`'s pause toggle because `HUDContainer` comes after `WorldContainer`; preview, level, exact HP, attack; "Mejoras" rows from `PlayerStats.get_run_upgrade_preview`). `BuildingMenu` (`scripts/ui/BuildingMenu.gd`): `TabBar` Producción/Defensa (tab index = `Module.SlotType`), cards with cost colored by resource and disabled when unaffordable/wrong slot size, native `tooltip_text` from `Module.DESCRIPTIONS` + `Module.describe_effect()`, chosen slot outlined via `BuildingSlot.set_highlighted()`; public API `open_menu(slot)`/`close_menu()` unchanged. `HUDController` binds `PlayerStats.stats_changed` (portraits) and `ResourceManager.resource_changed`/`production_changed` directly. Instantiated by `Main.gd` into `HUDContainer` (a sibling of `WorldContainer`, not a child of `Main2d.tscn`) — `HUDController` is fully self-wiring (autoload/group lookups only), so its own host in the tree doesn't matter. `HUDController` still adds itself to the `"hud"` group and exposes `show_simple_tooltip`/`hide_simple_tooltip` + a `StatTooltip` node — these are load-bearing for `StorePanel.gd` (pause-menu HP-upgrade store, unrelated to the old card system), not just HUD self-use. **Minimap** (`scripts/ui/hud/Minimap.gd`, `Control` + `_draw()`): created in code by `HUDController._add_minimap()` (bottom-right of `$Control`, not in `HUD.tscn`); draws revealed zones (powered rooms gold), the hero's zone and the exit outline only while `ExitIndicator.is_hint_visible()`. Resolves `RoomManager`/`Player`/`ExitIndicator` in `_ready` (works because `Main.gd` adds the world before the HUD) and redraws only on `room_revealed`/`room_powered`/`Player.zone_changed`/`ExitIndicator.hint_changed`.

## When picking up gameplay work here

`Main2d.tscn` has a per-floor seeded room/corridor graph (`MapGenerator` → `MapLayout` → `RoomManager.build_from_map()`, fallback `resources/maps/fallback_layout.tres`), a spawned hero positioned by zone (`Player.current_zone_id`), and click-a-connected-zone-to-glide-there movement (`scripts/world/RoomManager.gd`/`RoomZone.gd`, `scripts/core/movement/PlayerActionController.gd`, `scripts/core/actions/MoveAction.gd`) — see `feature/dote-resource-system`. As of `feature/dote-core-gameplay-loop` the full DotE loop is wired end to end: `DoorTurnSystem` advances the global turn, ticks `ResourceManager` (flat + Generator-module bonus), and spawns enemies on open; rooms can be Dust-energized to unlock `Module` build slots (economy/defense); grabbing `El Nexo` in `start_room` starts a door-blocked `ExtractionManager` extraction phase with periodic dark-room enemy waves; reaching `vault_room` (the `is_exit_room` zone) with the nexo triggers victory. There is still no real dungeon generation or targeting/combat beyond the flat tick-damage models in `Module.take_damage()`/`Enemy.take_damage()` — no dice rolls, no crit/miss, no `CharacterStats` involvement for non-heroes. Before building a new `BaseAction` subclass (attack, ability, etc.), look at `MoveAction.gd` (hero) or `EnemyMoveAction.gd` (enemy, re-reads speed per leg) as reference implementations: `can_execute()`/`execute()`/`finish()`, no AP or turn-consumption bookkeeping needed — movement and any future actions execute immediately, they don't go through a turn queue. The gameplay scene is never run standalone (F6 in the editor) once the orchestrator exists — it's instantiated by `Main.gd` into `WorldContainer`; run the project (F5) via `scenes/Main.tscn` instead, or `ManagerLocator.get_main_orchestrator()` returns null and any scene-flow button (Retry/Exit/Start/Leave) logs an error instead of working. Gameplay input (RoomZone/Door/EnergyButton/BuildingSlot/Nexo clicks) is entirely `Area2D.input_event`-driven — never read raw mouse input via `_unhandled_input`/`_input` in gameplay nodes and call `set_input_as_handled()` on it, since that runs *before* Area2D physics-picking in Godot 4 and silently swallows the click before it reaches any zone/door (this was a real bug in the old `PlayerActionController`). None of `feature/dote-core-gameplay-loop` has been manually verified in the Godot editor yet (no Godot binary was available in the environment that implemented it) — see the plan file / PR description's verification checklist before assuming the loop plays correctly end to end.
