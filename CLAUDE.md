# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

QUEST: 2D tactical game built in Godot 4.6, GDScript only (no C#/.NET), GL Compatibility renderer. A menu/character-select/save-slot shell, run under a `Main.tscn` scene orchestrator, around a tactical-grid gameplay scaffold (`Main2d.tscn`): pick a hero, spawn onto a placeholder `TileMapLayer` floor with real HP/AP stats, BFS-computed blue/yellow movement ranges, and two-click AP-costing movement. Supports Steam multiplayer (Host/Join via GodotSteam lobbies with auth-ticket validation) alongside the offline single-player flow.

**Removed in `refactor/total-gameplay-wipe`:** the previous card-driven combat, procedural dungeon generation, and enemy AI systems were fully deleted (not archived). If you go looking for `MapManager`, `CombatCardSystem`, `EnemyManager`, `CardData`, the old dungeon generation, or the old contents of `scripts/core/{enemy,combat,cards,effects}` / `scripts/world/{rooms,dungeon}`, it no longer exists — don't try to "fix" references to it, and don't assume any design notes about it still apply. `scripts/core/movement/` was also wiped, but has since been rebuilt from scratch in `feature/tactical-grid-ap-controller` (see below) — it is not the old pre-wipe movement code.

## Commands

No build system, linter, test suite, CI, or export presets exist in this repo. Only real dev commands:

```bash
godot --path . --editor   # open in editor
godot --path .             # run the game
```

If asked to add tests/lint/CI, there is nothing existing to hook into — treat it as new infrastructure, not "run the existing suite."

## Architecture

**Autoloads** (project.godot `[autoload]`):
- `PlayerStats` (scripts/core/stats/PlayerStats.gd) — persistent player base stats (HP/STR/MAG/DEX/AP), active upgrades, runtime `CharacterStats`; emits `stats_changed`/`player_died`. `register(stats)` binds a live `CharacterStats` node and re-applies base stats + upgrades onto it via `refresh_stats()`.
- `SaveManager` (scripts/managers/SaveManager.gd) — persists progression/upgrades/run cycle/slots/`selected_character_id` to `user://slot_<id>.cfg`. `apply_character_selection(id)` looks up `CharacterDatabase`, pushes base stats onto `PlayerStats`, and saves.
- `CurrencyManager` (scripts/managers/CurrencyManager.gd) — facade over `SaveManager.gold`, debounced persistence, emits `gold_changed`.
- `ThemeManager` (scripts/core/theme/ThemeManager.gd) — builds reusable `StyleBoxFlat`s for UI/menus.
- `SettingsManager` (scripts/managers/SettingsManager.gd) — persists UI SFX volume (click/hover), audio bus volumes (Master/Music/SFX/UI via `AudioServer`), video settings (window mode/resolution/vsync/FPS limit via `DisplayServer`/`Engine.max_fps`, applied automatically in `_ready()`) and gameplay screen-shake intensity to `user://settings.cfg`, emits `settings_changed`/`volume_changed`.
- `SteamManager` (scripts/network/SteamManager.gd) — Steam API init (AppID 480), Steam auth-ticket issuance/validation, `connected_clients`/`pending_clients` peer↔steam_id bookkeeping; owns a child `SteamLobbyManager` (scripts/network/SteamLobbyManager.gd, not an autoload) that handles lobby create/join/leave and `SteamMultiplayerPeer` wiring.
- `FPSOverlay` (scripts/ui/overlays/FPSOverlay.gd) — toggleable FPS counter overlay, driven by `SettingsManager.show_fps_overlay` (Video tab).

**`ManagerLocator`** (scripts/managers/ManagerLocator.gd) is the central indirection point: wraps autoload access (`get_save_manager`, `get_currency_manager`, `get_player_stats`, `get_settings_manager`, `get_steam_manager`) and group-based lookup for singletons that are *not* autoloads (`get_game_state_manager()` via `game_state_manager` group, `get_main_orchestrator()` via `main_orchestrator` group, `get_floating_text_manager()` via group, lazily instantiating on the scene root if absent). Fetch managers through this rather than raw autoload names or ad-hoc `get_tree().get_first_node_in_group()` calls.

**`Main` orchestrator** (`scenes/Main.tscn`, `scripts/managers/Main.gd`) — the project's `run/main_scene`. Owns four containers: `WorldContainer` (Node2D, hosts a `Main2d.tscn` instance during gameplay), `UIContainer` (CanvasLayer, hosts `MainMenu.tscn`/`WaitingRoom.tscn`), `HUDContainer` (plain Node, hosts a `HUD.tscn` instance during gameplay), `TransitionOverlay` (CanvasLayer, layer 200, a full-screen `ColorRect` faded via `MenuTransitionFX`). Public API — `show_main_menu()`, `start_gameplay()`, `go_to_waiting_room()`, `reload_gameplay()`, `return_to_main_menu()` — replaces all `get_tree().change_scene_to_file()`/`reload_current_scene()` calls project-wide; callers reach it via `ManagerLocator.get_main_orchestrator()` (never a raw node path), always null-check the result (it's null if a scene like `MainMenu.tscn`/`Main2d.tscn` is run standalone via the editor's "Play Scene", F6, instead of through `Main.tscn` via F5/"Play Project") and log via `QuestLogger` rather than crash. If `run/main_scene` in `project.godot` is ever hand-edited outside the Godot editor while the editor has the project open, the editor's in-memory main-scene setting is stale until the project is reloaded/reopened — restart the editor after such an edit.

**`GameStateManager`** (scripts/managers/GameStateManager.gd) — scene-instantiated (not an autoload) gameplay state machine: `State` enum ACTIVE/PAUSED/DEAD. Other systems call its `can_process_*` helpers to gate logic, and it emits `state_changed`/`pause_requested`/`resume_requested`/`death_entered`.

**`TurnManager`** (scripts/core/actions/TurnManager.gd) + **`ActionQueue`** (scripts/core/actions/ActionQueue.gd) — TurnManager registers/unregisters actors and drives turn sequencing (`begin_turn`/`process_turn_end` duck-typed on actors), refilling AP via the actor's `CharacterStats` each turn; ActionQueue serially executes queued `BaseAction`/`WaitAction`/`MoveAction` instances, emitting `action_finished(action, result)`. `request_pass_turn(actor)` is the entry point for the HUD's "Pasar Turno" button. A queued action with `consume_turn = false` (e.g. `MoveAction`) only ends the turn once the actor's `current_ap` hits 0 — otherwise the actor can queue another action in the same turn.

**`Player`** (scripts/core/player/Player.gd) — `Node2D` actor: owns a `CharacterStats` child, a `grid_pos: Vector2i`, and an `AnimatedSprite2D`. `configure(character_data)` (called before `add_child()`) stashes the selected `CharacterData` for `_ready()` to apply (`sprite_frames`); `set_grid_position(cell, tilemap)` snaps `grid_pos` + `global_position` via `GridUtils.cell_to_world()`. Implements the `begin_turn`/`process_turn_end`/`can_accept_input` contract `TurnManager` and `TurnButtonController` expect.

**Tactical movement** (`scripts/core/movement/`) — `GridUtils.gd` (cell↔world conversion against a `TileMapLayer`), `MapNavigationHelper.gd` (4-directional BFS from a `Vector2i` origin; a single pass returns both the 1-AP "blue" and 2-AP-dash "yellow" reachable-cell sets — a move never costs more than 2 AP even for characters with `base_ap > 2`, e.g. `rogue.tres`), `PlayerActionController.gd` (hover preview / click-to-select / click-again-to-confirm / right-click-cancel state machine, driven by `_unhandled_input`, rendered via a second `Highlight` `TileMapLayer` sibling of `Main2d.tscn`'s `Floor`). Movement itself executes as `scripts/core/actions/MoveAction.gd`, a `BaseAction` subclass (`consume_turn = false`) that tweens the `Player` along a BFS path and calls `CharacterStats.spend_ap()`.

**`Logger`** (scripts/core/utils/Logger.gd, `class_name QuestLogger`) — categorized/leveled logging (`Category`: GENERAL/COMBAT/CARDS/MAP/STATE/ACTIONS/SAVE/UI/CAMERA/NETWORK; `Level`: DEBUG/INFO/WARN/ERROR), replacing raw `print()` calls project-wide. Use it for new diagnostics instead of `print()`.

**Multiplayer flow**: Main menu "Iniciar Partida" opens `NetworkModeSelect` (scenes/NetworkModeSelect.tscn) with Host/Join/Offline. Host creates a Steam lobby (`SteamLobbyManager.create_lobby`, Friends Only) then picks a save slot via `SaveSlotSelector` (script on `scenes/SlotSelection.tscn`, not its own scene); Join opens the Steam friends overlay and joins via `join_requested`/`lobby_joined`. Joining clients must pass Steam auth-ticket validation (mandatory-blocking, 15s timeout) before `SteamManager.connected_clients` counts them as real players. Both paths land in `scenes/WaitingRoom.tscn` before the host starts gameplay; Offline is unchanged in shape (`SlotSelection.tscn` → `CharacterSelection.tscn` → gameplay, no networking) but every transition now goes through the `Main` orchestrator (`ManagerLocator.get_main_orchestrator().start_gameplay()` / `.go_to_waiting_room()` / `.return_to_main_menu()`), not `change_scene_to_file()`.

**`Main2d.tscn` gameplay scene** (scripts/managers/Main2d.gd): instantiated by `Main.gd.start_gameplay()`/`reload_gameplay()` into `WorldContainer` (no longer a directly-run scene, and no longer owns a static `HUD.tscn` child — HUD is instantiated separately into `Main.gd`'s `HUDContainer`). On `_ready()` it resolves `active_character_id` from `SaveManager.get_selected_character_id()`, ensures a `GameStateManager` child exists, spawns `Player.tscn` at grid cell `(1, 1)` on its `Floor` `TileMapLayer` (`configure(character_data)` + `set_grid_position()`), wires a `TurnManager` around it, sets up `PlayerActionController` (2-click movement), and connects pause/death overlay signals. Owns `Floor` (scripts/world/FloorGenerator.gd, a `TileMapLayer` filled with a placeholder floor tile at `_ready()`, `resources/tileset/placeholder_tileset.tres`) and `Highlight` (a second `TileMapLayer`, `resources/tileset/highlight_tileset.tres`, painted by `PlayerActionController` for the blue/yellow movement-range overlay and the hovered/selected path preview). `Main2dDeathHandler.gd` presents the death overlay/run summary (unchanged, pure presentation helper).

**HUD** (`scenes/HUD.tscn`, `scripts/ui/hud/HUDController.gd`): trimmed to exactly three widgets — HP bar/label, AP label, "Pasar Turno" button (`scripts/ui/hud/StatPanelUI.gd` formats them, `scripts/ui/hud/TurnButtonController.gd` wires the button to `TurnManager.request_pass_turn`). Instantiated by `Main.gd` into `HUDContainer` (a sibling of `WorldContainer`, not a child of `Main2d.tscn`) — `HUDController` is fully self-wiring (autoload/group lookups only), so its own host in the tree doesn't matter. `HUDController` still adds itself to the `"hud"` group and exposes `show_simple_tooltip`/`hide_simple_tooltip` + a `StatTooltip` node — these are load-bearing for `StorePanel.gd` (pause-menu stat-upgrade store, unrelated to the old card system), not just HUD self-use.

## Directory layout

- `scripts/core/` — `actions` (BaseAction/ActionQueue/TurnManager/WaitAction/MoveAction), `movement` (GridUtils/MapNavigationHelper/PlayerActionController), `player` (Player.gd), `stats` (PlayerStats/CharacterStats/CharacterData/CharacterDatabase/StatBalance/ModifierStack), `theme`, `utils`
- `scripts/managers/` — SaveManager, CurrencyManager, SettingsManager, GameStateManager, ManagerLocator, `Main.gd` (root scene orchestrator), Main2d/Main2dDeathHandler
- `scripts/network/` — SteamManager (autoload), SteamLobbyManager (Steam lobby/matchmaking)
- `scripts/ui/` — `hud` (HUDController/StatPanelUI/StatIcon/TurnButtonController), `menus` (incl. `MenuTransitionFX.gd` shared fade/scale tween helper used by `BaseMenu`/`BaseSubPanel`/`Main.gd`'s `TransitionOverlay`, `StorePanel`/`StoreUpgradeCard` stat-upgrade store), `overlays` (incl. `FPSOverlay.gd`), `visual` (FloatingText/FloatingTextManager)
- `scripts/world/` — `FloorGenerator.gd` (fills `Main2d.tscn`'s `Floor` `TileMapLayer` with the placeholder floor tile)
- `resources/` — `.tres` data: `characters/{warrior,mage,rogue,tank}.tres` (portraits, base stats, shared `sprite_frames`, consumed by `CharacterDatabase`), `tileset/{placeholder,highlight}_tileset.tres`, `sprites/shared_player_idle_frames.tres`
- `assets/texture/enviorment/` — placeholder floor (`tileset_placeholder.png`) and movement-range highlight (`highlight_placeholder.png`) tile art (checked-in PNGs, no real tile art exists post-wipe — see `resources/tileset/`)

## When picking up gameplay work here

`Main2d.tscn` now has a real `TileMapLayer` floor, a spawned hero with grid position, BFS-computed 1-AP/2-AP movement ranges, and two-click move confirmation (`scripts/core/movement/`, `scripts/core/actions/MoveAction.gd`) — see `feature/tactical-grid-ap-controller`. There is still no targeting, combat, enemies, or dungeon generation. Before building a new `BaseAction` subclass (attack, card, etc.), look at `MoveAction.gd` as the reference implementation: `consume_turn = false`, spend AP via `CharacterStats.spend_ap()`, `finish()` on completion — `TurnManager` ends the turn automatically once AP hits 0, no per-action turn-end bookkeeping needed. The gameplay scene is never run standalone (F6 in the editor) once the orchestrator exists — it's instantiated by `Main.gd` into `WorldContainer`; run the project (F5) via `scenes/Main.tscn` instead, or `ManagerLocator.get_main_orchestrator()` returns null and any scene-flow button (Retry/Exit/Start/Leave) logs an error instead of working.
