# Guardado entre pisos (session/guardado-19)

Sobre audio-18. Solo offline, se guarda el inicio de cada piso desde el 2. Sin cambios de balance ni contenido.

- **Qué/cuándo:** `Main._reload_world(false)` (= `advance_floor`, piso 2+) llama `_save_run()` *después* de liberar el `Main2d` viejo (sigue corriendo durante el fundido: una última baja tiene que contar) -> `SaveManager.save_run(Main.capture_run())`: una clave `[run] state` = {floor, run_seed, difficulty, heroes (elegidos), recruited, lost, run_stats, stats (`PlayerStats.get_run_state`: niveles+perks), inv (`PartyInventory.get_state`), res (`ResourceManager.get_state`: recursos+investigación), seen_types}. Solo el inicio del piso: el mapa sale de `run_seed` (determinista), la vida está llena al empezar cada piso, el bono de Brasas al bajar lo suma otra vez `FloorManager.setup`. Nunca online, nunca en el Tutorial, nunca sin ranura cargada.
- **Continuar:** `SaveManager.get_saved_run(slot)`/`has_saved_run`/`clear_run`; `MainMenuFlow._on_slot_selected` (offline) en una ranura con partida abre `continue_dialog` (`ConfirmationDialog`: "Continuar partida (piso N)" / "Nueva partida" / "Volver") -> `Main.continue_run()` = `_pending_run` + `start_gameplay(floor)`, que tras `_begin_new_run()` corre `_restore_run()` con las APIs `apply_state`/`apply_run_state` del co-op (`PartyInventory.reset()` ahora limpia `_applied_hash` para poder aplicar el mismo estado dos veces). Botón "RANURA N (PISO M)" + línea en el resumen.
- **Borrado:** `Main2d.finish_run` (derrota, victoria final, host perdido) y `Main.start_gameplay` de una partida nueva offline que no es tutorial. La confirmación de salida de la pausa (`PauseMenu.exit_message()`) dice que se pierde el piso y se retoma desde su inicio; online, que el co-op no guarda. `NetworkModeSelect` muestra `COOP_NO_SAVE`.
